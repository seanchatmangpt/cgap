## Measured (llvm-size on the linked ELF, exit 0)
Baseline, 4 exports (wasm_version, wasm_unpack_1bit, wasm_rle_decode,
wasm_decode_page_body_w4): text 2286, data 0, bss 0.
Symbol sizes: rle_decode 0x212, w4 decode 0x1ca, unpack_1bit 0xd2,
compiler_builtins memcpy 0x186, version 0xa.
bss is 0 because the 1 MiB HEAP is `static` and never referenced after the
LTO fold. The footprint is code only.

## Divergences (the doc yields to reality)
1. `cgap_arrow::bitmap` is `#[cfg(not(target_os = "none"))]`, so
   `wasm_mask_words` cannot build on riscv32imc-none. The sandbox stubs it
   out, so it is NOT in the 2286 B figure. The 5-export footprint is
   UNVERIFIED on riscv.
2. riscv32imc has no A-extension, so `compare_exchange_weak` does not exist.
   The sandbox bump allocator uses a plain load/store. This is a sandbox-only
   shim, and the shim adds no atomic code to the count.
3. The crate's real subject is wasm32-wasip1 plus wasm-opt (scripts/footprint.sh).
   That path was not run. The riscv figure is not a wasm footprint number.

## Anti-vacuity mutation (flipped)
Removing the `wasm_rle_decode` reference from the caller moved text
2286 -> 1222 (build exit 0, mutation applied in the sandbox). Restoring
main.rs (sha256 1d6a9721...f029 both before and after, mtime touched) gave
text 2286 again. The measurement tracks the real code.
