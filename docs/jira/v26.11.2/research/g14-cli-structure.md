# R14 — ggen CLI structure (Explore brief)

Lane: R14. Source: `/Users/sac/ggen`. Claims cited file:line. Purpose: cgap crates/cli docs.

## Two distinct CLI systems

1. **ggen's own CLI** (crates/ggen-cli) — hand-written Rust using clap-noun-verb v26.x
   auto-discovery (the "dogfood" CLI).
2. **The zero-code CLI compiler** (packs/clap-noun-verb-*-pack, 6 packs) — what ggen
   generates for consumers. cgap's CLI is in this category: RDF ontology → generated
   generated_cli.rs / generated_behavior.rs / generated_boundaries.rs + one hand-written
   seam src/custom_handlers.rs.

## clap-noun-verb mechanics (ggen's own CLI)

- Workspace pins `clap-noun-verb = "=26.9.1"` + macros (Cargo.toml:148-149); ggen-cli deps
  both (crates/ggen-cli/Cargo.toml:180, 212).
- Verb registration: plain functions annotated `#[verb]` in cmds/ modules; noun from module,
  verb from fn name — `pub fn inspect(manifest: String)` under cmds/doctor.rs →
  `ggen doctor inspect` (cmds/doctor.rs:12-19). Args plain typed params (String/bool/PathBuf).
- Noun registry: `#[linkme::distributed_slice(::clap_noun_verb::cli::registry::__NOUN_REGISTRY)]`
  statics (cmds/mod.rs:36-167); descriptions registered explicitly because "runtime source
  scraping is not reliable" outside the repo (:1-5).
- Entry/routing: `cli_match()` lib.rs:118-244. Preprocessors: `inject_default_verbs`
  (:259-280) — bare nouns map to default verbs (`ggen sync` → `sync run`, `ggen doctor` →
  `doctor run`, `ggen receipt` → `receipt verify`; noun-level --help never rewritten);
  `expand_json_flag` (:369-383) — `--json` → global `--format json`, explicit --format wins.
- Telemetry redirection: clap-noun-verb writes `.clap-noun-verb/{ocel.json,receipts.jsonl}`
  per invocation, breaking sync determinism; ggen defaults these to
  `$TMPDIR/ggen-cli-telemetry` unless env overrides (lib.rs:128-140). **Relevant to cgap** —
  determinism footnote.
- Cross-crate verb registration: ggen-engine registers verbs via distributed_slice, pulled
  in by `use ggen_engine as _;` (lib.rs:101, comment 96-100) — Rust drops unreferenced
  extern-crate code; the `as _` import is the seam.
- `--version --verbose` prints build provenance via
  `ggen_engine::build_provenance::describe()` (lib.rs:214-224, cmds/mod.rs:176-191).
- Programmatic run (Node addon): `run_for_node(args)` with hand-maintained KNOWN_NOUNS
  allowlist, early-exit on unknown subcommand (lib.rs:448-571).
- Legacy `ClapNounVerbPreset` scaffolding superseded by the six-pack compiler
  (conventions/presets/clap_noun_verb.rs:14-60).

## Generated vs hand-written (ggen's own CLI)

Mostly hand-written; exactly one generated file: src/generated_commands.rs — "DO NOT EDIT —
generated by root ggen.toml rule cli-commands-reference from imported CLI ontologies. Edit
RDF law, then ggen sync run" (generated_commands.rs:1-4). Contains COMMANDS_REFERENCE,
DEFAULT_VERBS, describe_command(), ontology-derived inject_default_verbs. Generation rule:
[[generation.rules]] name="cli-commands-reference", inline SPARQL over cli:Command
individuals, template .specify/templates/cli/commands-reference.rs.tera, output
crates/ggen-cli/src/generated_commands.rs, mode Overwrite (ggen.toml:120-133). #[verb]
bodies hand-written; domain logic in ggen-domain/ggen-engine; CLI is a thin bridge
(lib.rs:1-15).

## The six-pack zero-code compiler (cgap-relevant pattern)

schema-pack (RDF law only — cnv:Cli/Noun/Command/Argument/Behavior/Boundary; "intentionally
no individuals, so composing the schema pack cannot alter a consumer's public command
surface", schema-pack/ontology.ttl:1-30) → crate-pack (Cargo.toml.tmpl, main.rs.tmpl,
lib.rs.tmpl emitting `pub mod custom_handlers;` only when graph has cnv:CustomBehavior
commands, lib.rs.tmpl:20-25) → routing-pack (generated_cli.rs, force:true) → behavior-pack
(generated_behavior.rs) → boundary-pack (generated_boundaries.rs) → verification-pack
(tests/zero_code_cli.rs real-binary tests + command-reference.md.tmpl).

- generated_cli.rs: frontmatter to/force/sh_after: rustfmt (routing-pack
  templates/generated_cli.rs.tmpl:2-4). SPARQL selects commands with behavior-kind VALUES +
  typed arguments (full clap surface) + nouns (:5-85). Per command emits
  `#[verb("verb","noun")] fn <noun>_<verb>(typed args) -> Result<Value>` packing args into
  serde_json::Map and dispatching (:111-148): closed behaviors →
  `generated_behavior::execute(BehaviorSpec::X{...}, inputs)`; custom →
  `crate::custom_handlers::<noun>_<verb>(inputs)` (:147-148) — the ONLY consumer seam.
  Reserved keywords r#-prefixed; value-kind→Rust-type closed mapping (tmpl:105,115). Noun
  registration via same linkme statics (:189-198). **Generated wiring proofs** embedded as
  #[cfg(test)] mod generated_route_proofs (:206-241): every_admitted_command_became_one_
  registered_verb, no_consumer_handler_seam_survives_generation (no legacy handlers::, no
  todo!), every_custom_command_routes_to_its_own_handler. Proven load-bearing by sabotage
  test (misdirected routing to a compiling decoy handler must fail) —
  crates/ggen-engine/tests/custom_behavior_e2e.rs:281-342.
- generated_behavior.rs: "Ontology values select variants of this enum; they can never inject
  Rust source or name an unresolved consumer handler" (behavior-pack
  generated_behavior.rs.tmpl:11-12). BehaviorSpec enum: StaticJson | Echo | Expression |
  FilesystemWrite | FilesystemList | Refusal (:21-44) — six primitives, no string-selected
  handler. Checked integer arithmetic; div-by-zero/non-finite refuse closed (:100-178).
- custom_handlers.rs: frontmatter to/src/custom_handlers.rs, **unless_exists: true**,
  skip_empty: true (crate-pack custom_handlers.rs.tmpl:2-5); SPARQL selects only
  cnv:CustomBehavior commands (:6-15); emits `pub fn <noun>_<verb>(inputs: Map) ->
  Result<Value>` todo! stubs (:30-35); header "GENERATED ONCE ... never overwritten ...
  sole consumer handler seam" (:17-25). Lifecycle: first sync scaffolds todo! stubs
  (deliberately fails to compile until hand-completed); hand-completion survives resync
  byte-identically (unless_exists); real binary dispatch verified (custom_behavior_e2e.rs:
  200-279). Ontology declaration one line: `cnv:PricingBehavior a cnv:CustomBehavior .`
  (:156). Runnable proof: examples/zero-code-custom-handler-demo/.

## Notes for cgap docs

- cgap's manifest_patch.py has no ggen counterpart — ggen does post-render mutation via
  frontmatter sh_after hooks; document cgap's patcher as the consumer-side equivalent.
- Telemetry redirection for determinism (lib.rs:128-140) worth replicating.
- A generated CLI and hand-written cmds/ can coexist in one binary (both feed
  __NOUN_REGISTRY).
- Canonical consumer doc to crib: docs/how-to/clap-noun-verb/zero-code-cli.md (238 lines) —
  authority boundary table: ontology = application authority; packs = manufacturing law;
  generated Rust = derived product; generated tests = executable falsifier.
