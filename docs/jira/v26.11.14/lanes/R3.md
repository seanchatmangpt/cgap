# R3 (Reduce): chains-* alloc columns

Standing: PARTIAL. Measured and one reduction leg landed; the larger
levers sit in cgap-ffi (outside lane scope) and are not applied.

Method: `CARGO_TARGET_DIR=/tmp/target-R3 cargo bench -p bench --bench
chains-<x>` (bench profile, divan 0.1.21, 100 samples), x in ingress,
parquet, bn3, seal, sovereign: all rc=0. Host: Linux 4 vCPU. Load average
was 0.1 at start but 5-7 mid-run (sibling lanes, e.g. Ra2 loadgen on
chains-ingress). Timings are TARGETs/informational, contention-suspect;
alloc counts are deterministic and load-independent.

## Profiler install (who can show alloc columns)
- bn3, parquet, sovereign install `divan::AllocProfiler`: columns valid.
- chains-ingress and chains-seal install NONE (grep). Their absent
  columns were therefore VACUOUS, not 0.
- Corroboration (court): /tmp/R3-sandbox copy with a profiler appended to
  both files; both re-run rc=0, still zero alloc columns => timed loops of
  ingress and seal are 0-alloc (CORROBORATED in sandbox only). Anti-vacuity:
  the same profiler in sibling binaries (parquet encode_arm) prints
  nonzero columns, so a flip is observable. Shared-tree files NOT edited
  (a profiler would perturb Ra2's ingress timing band) - recommend
  landing the 2-line install after Ra2.

## Reduction landed (crates/bench only)
`crates/bench/benches/chains-parquet.rs`: new sibling leg
`encode_into_arm` (`rle_encode_into`, reused buffer). Baseline
`encode_arm` untouched as the positive control. Run:
`cargo bench -p bench --bench chains-parquet -- encode` rc=0.
Result: encode_into_arm 65536 and 1048576 show NO alloc columns (0 alloc,
0 grow) vs baseline 1 alloc + 13/17 grows; wire length asserted equal;
median 409 vs 408 us (65536), 7.16 vs 6.66 ms (1048576, noisy). Named
mutation: swap body to `rle_encode` -> alloc column reappears (the
baseline leg is that mutant live in the same binary).

## Candidate reductions NOT applied (outside crates/bench)
1. cgap-ffi `cgap_eval_bn3`: decode rule table once per rodata, not per
   frame (~33 allocs/frame, ~15 grows/frame). Largest lever. Needs a
   caller-held decoded handle or cached decode; ABI-visible -> owner lane.
2. cgap-ffi commit path 3 allocs/frame.
3. bn3 closure_ladder 223 grows: pre-size derived-fact buffers
   (cap=237568 is known up front per bench log).
