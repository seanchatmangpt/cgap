# F9 - egress_ring_court flake

Standing: ALIVE (test-side race fixed; library untouched).

## Reproduction
Pre-fix, binary run 60x (loadgen exited on a usage error, so effectively
unloaded): 5/60 failed, all in `zero_alloc_serve_court`:
"window allocated 1 times" (:248), "parse_page allocated 2 times" (:265).
Logs: scratchpad FAIL15/16/18/32/48.log.

## Root cause
`COUNT` was a process-global AtomicUsize. The `SERIAL` mutex only serializes
the five test bodies; the libtest main thread (result reporting, thread
bookkeeping) allocates outside it and bumped the counter mid-window.
Not a cgap-git library race (egress_ring.rs untouched).

## Fix (egress_ring_court.rs only)
Counter is now a per-thread const-init `thread_local Cell<usize>`
(`Count` wrapper keeps call sites); assertions and mutation arms unchanged.

## Proof
- Post-fix, 60 runs under `/tmp/f9-loadgen combined 2 4` (alive, verified):
  0 failures.
- Anti-vacuity mutation (sandbox /tmp/f9-sbx, rustc --test): inject
  `vec![0u8;8]` into `serve_ipc_page` -> "serve_ipc_page allocated 1 times",
  1 failed. Restore: sha256-exact + touch; clean rebuild 5 passed.
- Control arm (`snapshot_owned` delta>0) still asserts the instrument fires.
